# Persona — 目標使用者輪廓

> **白話**：Persona 是「虛構但很具體的一個代表性使用者」，用來讓開發者做決策時有畫面感——不要抽象地想「使用者」，而是想「小雅會不會這樣做」。

---

## Primary Persona（主要使用者）：小雅

### 基本輪廓

| 項目 | 內容 |
|---|---|
| **年齡** | 32 歲 |
| **職業** | 台北科技業行銷主管 |
| **收入** | 月薪 8–10 萬 |
| **居住** | 台北大安區獨居 |
| **飲酒習慣** | 一週 2–3 次，在家喝，一次一杯 |
| **酒櫃現況** | 5–8 支酒（葡萄酒為主，少量清酒） |
| **消費場景** | 全聯、家樂福、City'super、進口酒專門店 |

### 她的一天

下班晚上 8 點回家，做了簡單的鴨胸義大利麵。想開一支上週在 City'super 買的紅酒，酒標寫「Château XXX 2019, Bordeaux」。她的疑問：

- 「2019 是好年份嗎？」
- 「這款去年喝過一次覺得偏酸，這次會不會不一樣？」
- 「背標中英文都翻得很文青，但沒告訴我實際會喝到什麼」

### 痛點

1. **看不懂酒標術語**：AOC、Grand Cru、辛口、精米步合⋯⋯
2. **不知道年份差異**：買了兩支同款不同年份的酒，喝完覺得差很多但不知道為什麼
3. **背標資訊行銷味太重**：「果香濃郁、單寧細緻」——每支都這樣寫，形同沒說
4. **請教侍酒師太害羞**：怕問了顯得外行，或懶得專程跑一趟

### 動機

- 想從「喝酒」進階到「懂酒」，但不想上正式品酒課
- 喜歡在 IG 分享品飲心得，需要有內容可以寫
- 對「知識性內容」有好感，覺得「理解」本身就是享受

### 使用情境

- **開瓶前 3 分鐘**：拍下酒標，看報告，決定要不要今晚開
- **開瓶後對照**：喝一口後回頭看報告，驗證是否符合推測
- **買酒前**：在超市看到酒，先拍照查一下再決定

### 對這個產品的期待

- 快（10 秒內給答案）
- 白話（不要滿滿專業術語）
- 誠實（不要什麼酒都說好喝）

## Secondary Persona（次要使用者）：老陳

### 基本輪廓

| 項目 | 內容 |
|---|---|
| **年齡** | 45 歲 |
| **職業** | 小型進口酒商業務兼採購 |
| **經營型態** | 個人接單 + 少量店面 |
| **每月經手酒款** | 30–50 支 |

### 他的痛點

- 客戶常問「這年份怎麼樣」，他不可能每支都試過
- 想跟客戶說出「有故事、有依據」的介紹話術
- 官方 tech sheet 都英文，客戶聽不懂

### 使用情境

- 進新一批貨時，快速產生「這批酒的氣候背景」介紹卡
- 客戶詢問時，當場拿手機示範查詢，增加專業感

### 對這個產品的期待

- 資料要有出處（可以跟客戶說「這是 XX 資料庫的公開氣候資料」）
- 措辭要中性，不要有明顯的正評/負評（他自己會判斷怎麼跟客戶說）

---

## Anti-Persona（不是給誰用）

明確**不是這個產品的目標**，避免功能被拉偏：

- **專業侍酒師 / WSET 認證持有者**：他們有更完整的資料庫和訓練，不需要這種入門解讀
- **只喝威士忌/烈酒的重度玩家**：烈酒風味受氣候影響較小，這系統對他們幫助有限
- **完全不喝酒的人**：功能對他們無意義

---

## Persona 對設計決策的影響

| 決策點 | 因為 Persona 所以⋯⋯ |
|---|---|
| UI 語氣 | 白話 + 有溫度（小雅不喜歡教條）而非學術報告 |
| 措辭 | 「可能偏向」而非「絕對是」（老陳需要中性） |
| 資料來源標註 | 每個推測都顯示引用（兩位 persona 都需要信任感） |
| 回應速度 | 15 秒內完成（小雅在等待開瓶的空檔中使用） |
| 手機優先 | Streamlit 選擇支援手機瀏覽器（小雅站在超市貨架前使用） |
